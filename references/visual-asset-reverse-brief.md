# 页面反推素材与 Image 2

## 目的与边界

当文档的事实足够、但图片不足时，不改变页面去迁就泛化素材。先锁定页面主张、版式和文字安全区，再反推每张图片或视频应有的比例、图层、主体位置和生成提示词。

本规则从用户提供的 4 分 33 秒PPT制作视频提炼：其展示了“精准需求 -> 结构化大纲 -> 主题氛围图 -> AI补图 -> 动画”的顺序，以及产品矩阵、雪山时间线和前/中/后景拆分。已使用本地 Whisper 中文模型完成转写，并与可读屏幕字幕和画面对照。机器转写存在少量专有名词错字，因此仅采纳被多处上下文、画面或字幕共同支持的方法，不把不清楚的口播、营销承诺或具体工具名写成规则。

## 强制顺序

`页面主张与P码 -> 文本安全区 -> 视觉焦点 -> 素材图层 -> 槽位比例与裁切 -> 标题信号+风格词+主体+场景 -> 素材规格 -> Image 2提示词 -> 组合 -> 渲染QA`

先创建 `visual-asset-plan.json`，并运行 `validate-visual-asset-plan.mjs`。没有计划、来源策略或静态降级时，不调用生图。

## 标题反推与草图控制

### 标题反推提示词

每个 `source_strategy: imagegen` 资产先写四个字段，再组成完整提示词：

1. `title_signal`：页面结论或标题真正要让观众感到什么，不能只是章节名。
2. `style_keywords`：2-4个可执行的风格词，例如“纪实自然光、克制工业质感、低饱和蓝灰”。
3. `subject_description`：一个可见主体及其位置、尺度、朝向；多产品拆成多个 cutout。
4. `scene_description`：主体所处场景、前后关系、光线与颜色，不包含虚构的数字、文字、品牌或Logo。

### 草图控制构图

当页面有两个以上文字区、产品必须落在指定区域、需要制造景深，或生成图会影响流程/数据可读性时：

1. 用PPT形状画出文本区、主体框、背景块、前景遮罩或三角/透视结构；草图中不放最终文案。
2. 将草图导出为单独参考图，记录 `composition_control: sketch`、草图文件或可复现描述、目标比例和禁止覆盖的文字区。
3. Image 2 只生成背景、场景或单个可组合主体；文本、数据、连接线和Logo回到PPT中编辑。
4. 需要双重曝光或多景纵深时，先确定 `background -> midground -> foreground` 图层顺序，再分别生成/修图并合成；各层必须同一视角、光向和色温。

## 图层与比例

| 角色 | 适用 | 规格与构图 |
|---|---|---|
| `background` | 封面、场景、时间线 | 默认16:9；低细节区留给文本，画面只承载氛围或地点，不放生成文字 |
| `midground` | 建筑、环境、地图、氛围光 | 按槽位生成；与背景统一视角、光线、色温，不抢标题 |
| `foreground` | 人物、单品、设备、主体物 | 按实际槽位反推3:4、4:5或横向比例；主体完整，明确左右位置和文本留白 |
| `cutout` | 可编辑产品矩阵、人物叠加 | 独立单主体，不把多个产品和文字烙进一张图；需要透明时按 imagegen 的色键去背流程处理 |
| `texture` | 深色章节、文化/工业材质 | 只做弱层，不能替代事实图片或图表 |
| `motion` | M05/M08动态锚点 | 先有可读首帧；6-10秒低速循环，失败时回落静态首帧和顺序揭示 |

多主体产品页优先用独立、同视角同光线的 `cutout` 组合，再用PPT可编辑色块和文字排版。不要让Image 2一次生成带中文、数据、Logo和多产品说明的整页PPT图片。

## Image 2 调用规则

1. 缺少用户/官方/授权素材且 `image_policy` 允许生成时，加载 `imagegen`；默认使用其内置 Image 2 路径，不要求用户提供API Key。
2. 每次只生成一个明确资产或一个同资产的变体。项目正式使用前检查主体、构图、文本区、裁切、风格、伪文字/伪Logo和事实误导。
3. 提示词必须包含：资产用途、页面槽位、主体、环境、风格、构图、文字安全区、色彩光线、禁止项。生成图不得含文字、水印、Logo或图表数据，除非用户明确提供并允许使用。
4. 对真实地点、真实产品外观、真实人物、客户、工程成果、政策场景和数据证据，优先用户、官方或授权素材。AI图只能作概念/氛围补充，并在素材台账标为 `generated_illustrative`。
5. 生成图不合格时只做一次针对性重试；仍不合格则回退为授权素材、可编辑图形或留白，不把低质量AI图硬放进PPT。

对真实人像和真实产品补图，还必须遵守：

- 人像仅在具备授权时进行去背、裁切、光色和背景替换；不得换脸、虚构职业身份、改变服装所表达的身份事实，或以生成肖像替代需证明的真实人员。
- 产品可做去背、清洁修图、白底展示和场景合成，但不能改变型号、比例、结构、颜色版本、标识、性能或交付物状态。若这些信息重要，改用用户/官方图片。
- 场景合成中，真实产品和人物应保留为独立可替换图层；任何生成环境均标为 `generated_illustrative`。

## 视频与动态

Image 2 只负责静态位图。需要真实移动时：先保存经确认的静态首帧，再加载 `hyperframes` 生成可控的低速推拉、平移或蒙版循环；若没有可靠视频能力或播放环境，保留首帧并用M01-M03内容揭示替代。任何视频/GIF都不能承载唯一事实信息。

只在少文字、大主视觉页面使用 M05/M08。生成动态前，记录 `source_still_asset_id`、图像结构、焦点主体、运动路径、6-10秒时长、播放环境和静态降级。不能从首帧解释为何这样运动时，不生成视频；普通汇报页优先原生顺序揭示。

## 素材验收

- 文本安全区无遮挡，主体位置与分镜一致，可按槽位裁切。
- 相邻页面色彩、光线和视觉尺度一致；无AI乱码、伪Logo和不相关物体。
- 生成图没有作为真实证据使用；来源、提示词、页面、用途和替换边界已记录。
- 动态有静态首帧、播放条件和失败降级；PPT静态阅读仍成立。
