# 持续学习协议

## 目标

让每次PPT交付产生可复用经验，同时防止错误经验、客户敏感信息、模板资产和单次审美偏好污染全局规则。

## 学习循环

1. **查询**：分类完成后按I码、H码查询；默认同时返回稳定规则、候选建议和禁用模式，并按证据等级分组。
2. **跟踪**：制作过程中在scratch记录用户反馈、原方案、修改动作、结果和QA证据；同一反馈不重复抄写。
3. **自动候选**：每次最终交付通过门禁后，自动提炼并写入 `status=candidate`，不要求用户再次下达“总结”指令。
4. **修订**：用户继续修改时，新记录用 `supersedes` 指向旧记录；旧记录保留审计历史，但不再进入默认查询。
5. **接受**：只有用户明确表示满意、通过、采用或验收，才记录 `status=accepted`。沉默、离开任务或暂时没有后续消息都不是可验证的接受信号。
6. **抽象**：每类要点最多8项，自动去重，只保留跨项目可复用规则，不保存具体客户事实。
7. **升级**：同一规则必须由至少3个不同项目支撑、每个项目质量评分不低于85、没有事实/版权/播放硬失败，并经人工确认后，才升级为 `promoted` 的I×H通用规则。

## 证据等级

- `candidate / advisory`：交付QA通过但未获明确认可；后续可以参考，用于减少重复反馈，不能作为硬规则。
- `accepted / stable`：当前项目已获明确认可；可作为同I×H稳定经验，仍不能替代当前材料。
- `promoted`：跨至少3个项目验证并经人工确认；可作为同I×H默认规则。
- `rejected / avoid`：被明确否定或造成硬失败；默认规避。

## 必须记录

- `case_id`、日期和状态。
- `industry_code`、`scenario_code`、阶段和受众类型。
- 输入材料类型，例如多工作表Excel、PDF标准、Word方案、图片资产、既有PPT。
- `accepted_patterns`：用户接受且QA通过的做法。
- `rejected_patterns`：被用户否定或造成误解的做法。
- `stable_rules`：以后同类任务应默认遵守的规则。
- `style_variables`：本次采用但不可固化的颜色、模板、字体或版式偏好。
- `style_profile`：模板/品牌/参考作品的来源、使用模式、授权状态和抽象视觉规律；默认 `project_only`。
- `data_rules`：资料读取、口径、计算和来源要求。
- `qa`：页数、总分、交付完成、溢出、文件完整性、硬失败、数据追溯和用户确认状态。
- `supersedes`：存在后续修订时指向被替代的旧案例。
- `promotion`：`candidate`、`promoted` 等状态、支撑 case_id 和人工确认状态。

## 禁止记录

- 客户或个人名称、联系方式、账号、密钥、身份证明。
- 保密数字、完整预算、设备序列号、内部路径和未公开文件内容。
- 未经用户接受的推断、未经QA验证的设计结论。
- “蓝色更好”“必须18页”等单项目偏好作为全行业通用规则。
- 模板的原图、完整文案、Logo、截图、母版文件和未获授权的第三方设计资产。

## 经验优先级

`当前用户明确要求 > 当前原始材料 > 当前项目验收反馈 > 同I×H已接受案例 > 行业/场景默认规则 > 通用视觉默认值`

学习库只能帮助选择结构和避免旧错误，不能作为当前项目数字、事实或结论的来源。候选建议的优先级始终低于已接受经验。

模板学习只沉淀“为什么有效”的抽象规律，例如标题层级、图片比例、留白和动效节奏；用户自有或获授权模板可以服务当前项目，但其完整 style profile 不自动进入通用库。
