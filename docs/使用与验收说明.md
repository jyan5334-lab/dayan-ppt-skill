# 使用与验收说明

## 1. 入口与工作流

这个技能没有独立网页、按钮或后端服务入口，入口是 Codex 中的 `$dayan-ppt` 调用。用户提供材料后，按以下顺序推进：

| 阶段 | 操作 | 输出/状态 |
| --- | --- | --- |
| 1. 材料盘点 | 递归列出文档、工作簿、图片、视频、模板和既有 PPT；工作簿读取全部工作表 | `source-ledger.json`；确认材料范围 |
| 2. 分类 | 读取行业/场景矩阵，确定 `I×H`、受众、阶段和观看方式 | 分类卡；确认/推断/阻塞项 |
| 3. 证据架构 | 提取主张、关键数字、来源、口径和证据缺口 | `production-manifest.yaml`、`fact-claims.json` |
| 4. 计划校验 | 选择页面原型、图表语义、动效与静态降级 | `deck-plan.json`、`visual-asset-plan.json` |
| 5. 制作 | 使用 Presentations 能力生成可编辑 PPTX，保留版本并逐页渲染 | PPTX、渲染图、QA 记录 |
| 6. 验收 | 检查溢出、遮挡、来源、口径、页数、媒体、压缩包完整性和播放表现 | `已真实跑通`、`仅页面完成`、`被阻塞` 或 `需要人工配置` |
| 7. 学习 | 仅在交付完成、评分不低于 85、无溢出和硬失败时记录匿名候选 | `candidate`；明确验收后才可升级 |

## 2. 命令与契约

### 工作簿审计

```bash
python scripts/audit_workbooks.py <workbook...> --output <source-ledger.json>
```

用于记录工作表、非空单元格、公式、合并区域、星号标记和文件哈希。不能只审计活动表或汇总表。

### 事实校验

```bash
python scripts/verify_workbook_claims.py <fact-claims.json>
```

每个关键数字至少需要来源文件、工作表/页码、单元格/段落、单位、时间口径和状态。冲突或缺证据时不得进入正式版。

### 页面计划校验

```bash
node scripts/validate-deck-plan.mjs <deck-plan.json>
```

重点阻断：页面缺主张/证据/视觉焦点、数据缺来源单位周期、动效无静态降级、连续三页使用同一轮廓。

### 视觉素材计划校验

```bash
node scripts/validate-visual-asset-plan.mjs <visual-asset-plan.json>
```

重点检查标题信号、风格词、主体、场景、构图控制、文字安全区、图层、裁切、来源策略、负向约束和静态降级。

### 学习注册表回归

```bash
python scripts/test_learning_registry.py
```

用于确认候选记录、排序、去重、`supersedes` 和敏感字段拒绝逻辑没有回归。

## 3. 权限、API 与数据库边界

- **文件权限**：需要读取用户明确提供的材料和本仓库参考文件；需要写入用户指定的工作目录、渲染目录和学习候选记录。
- **外部访问**：默认不依赖外部 API。若用户明确授权使用官方资料、图片或 Image 2，应单独记录来源、许可和可替换边界。
- **密钥边界**：不读取、不提交、不写入 Git 的令牌、密码、私钥、客户资料或绝对路径。
- **API**：仓库没有 HTTP/REST/GraphQL 接口；可执行接口是上述本地 CLI 脚本及其 JSON/YAML 输入输出。
- **数据库**：仓库不创建或写入数据库；事实账本、计划、QA 和学习记录均为文件型产物。

## 4. 异常状态

| 状态 | 触发条件 | 处理方式 |
| --- | --- | --- |
| `BLOCKED: missing source` | 关键材料、工作簿或模板缺失 | 停止强结论，列出缺失项 |
| `BLOCKED: conflicting evidence` | 不同来源对同一事实不一致 | 保留双方来源，要求确认口径 |
| `BLOCKED: validation failed` | 计划校验器发现硬失败 | 修复计划后再排版 |
| `NEEDS_CONFIRMATION` | 受众、最终行动、外发口径或播放环境会改变结果 | 只提 1-3 个关键问题 |
| `ONLY_PAGE_COMPLETE` | 页面已经生成，但未完成渲染、数据或播放验收 | 不报告为可交付 |
| `NEEDS_MANUAL_CONFIG` | 缺少本机字体、Presentations 能力、外部素材或授权 | 明确人工配置与复验步骤 |
| `HARD_FAILURE` | 虚构数据、关键事实无来源、溢出、遮挡、文件损坏或虚称动画 | 不交付，回到对应阶段修复 |

## 5. 验收清单

### 生产前

- [ ] 已递归盘点用户范围内的材料，并核对工作簿全部工作表。
- [ ] 已确定 `I×H`、受众、阶段、观看方式和最终行动。
- [ ] 已区分 `confirmed`、`calculated`、`needs_confirmation`、`excluded`。
- [ ] `production-manifest.yaml`、`fact-claims.json` 和 `deck-plan.json` 可追溯。
- [ ] `validate-deck-plan.mjs` 与 `validate-visual-asset-plan.mjs` 通过。

### 交付前

- [ ] PPTX 可编辑，且未把静态截图当成唯一交付物。
- [ ] 每页已渲染并检查标题换行、正文溢出、孤立标点、专业词拆行、图表遮挡和连线穿字。
- [ ] 关键数字与事实账本一致；图表具备来源、单位、时间和口径。
- [ ] 图片来源/许可已记录；生成图未承担真实事实证据。
- [ ] 动效已实际嵌入，或明确标注为演讲备注/静态首帧降级。
- [ ] PPTX 压缩包完整，页数、页码、目录导航、页脚和媒体状态已核对。
- [ ] 无硬失败，综合评分达到 85 分或以上。

### 发布前

- [ ] 仓库只包含技能源文件、参考资料、模板、说明和已授权示例。
- [ ] 已排除 `.DS_Store`、`.tmp/`、`.codex-tmp/`、`.worktrees/`、`__pycache__/`、`.pyc`、PPTX 成品和客户原始材料。
- [ ] README 中的能力描述与本地源文件一致，没有把静态审查写成生产运行证明。
- [ ] 已记录当前分支、提交、远程仓库、推送结果和剩余风险。
